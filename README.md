# SciMath Test — เวอร์ชัน Cloud (Supabase + GitHub Pages)

ระบบรับสมัครสอบวัดความรู้วิทยาศาสตร์-คณิตศาสตร์ ที่ **ไม่ต้องเช่าเซิร์ฟเวอร์ PHP** —
หน้าเว็บเป็นไฟล์ HTML ล้วน host ฟรีบน GitHub Pages ส่วนข้อมูลทั้งหมดเก็บบนคลาวด์ของ Supabase
(ฐานข้อมูล PostgreSQL + ระบบล็อกอินเจ้าหน้าที่) ใช้แพ็กเกจฟรีได้สำหรับการรับสมัครหลักร้อยถึงหลักพันคน

```
ผู้สมัคร/เจ้าหน้าที่ ──► GitHub Pages (หน้าเว็บ HTML) ──► Supabase (ฐานข้อมูล + ล็อกอิน)
                              ▲
                  git push → GitHub Actions deploy อัตโนมัติ
```

## ความสามารถ

**ผู้สมัคร / ครู**
- **สมัครรายบุคคล** — กรอกใบสมัคร อัปโหลดรูปติดบัตร + **สลิปการโอนเงิน**
- **สมัครแบบโรงเรียน** — ครูที่ปรึกษากรอกครั้งเดียวสูงสุด 100 คน (วางรายชื่อจาก Excel ได้) โอนยอดรวม **สลิปเดียวทั้งกลุ่ม**
- **ครูที่ปรึกษา** (เลขบัตรครู + เบอร์โทร) — ติดตามสถานะทั้งกลุ่ม อัปโหลดรูปนักเรียนทีละคน แนบ/เปลี่ยนสลิป **พิมพ์บัตรทั้งกลุ่มพร้อมกัน**
- **เข้าสู่ระบบผู้สมัคร** (เลขบัตร + วันเกิด) — ดูสถานะอนุมัติ/เหตุผลที่ไม่อนุมัติ ส่งสลิปใหม่ พิมพ์บัตรประจำตัวผู้เข้าสอบ (สไตล์ mytcas) ดูผลสอบ
- **หน้าแรกแสดงสถิติ** จำนวนผู้สมัคร / อนุมัติแล้ว แยกระดับชั้น (ตัวเลขรวม ไม่มีข้อมูลส่วนตัว)
- **ข่าวสาร** — หน้ารายการ + หน้ารายละเอียดข่าว (รูปปก เนื้อหาเต็ม ลิงก์เอกสาร ข่าวปักหมุด)
- ตรวจผลสอบ · คู่มือ · ติดต่อ

**เจ้าหน้าที่ (แท็บเดียวจบ):**
- **ผู้สมัครสอบ** — ค้นหา/กรอง · กด **"ตรวจสอบ"** เพื่อดูรูป+สลิปแล้ว **อนุมัติ / ไม่อนุมัติ (พร้อมเหตุผล)** ·
  "อนุมัติและตรวจรายถัดไป" ไล่ตรวจต่อเนื่อง · ติ๊กเลือกแล้ว **อนุมัติหลายรายการ** · เพิ่มคนเอง · แก้ไข (รูป ห้องสอบ เลขที่นั่ง) · พิมพ์บัตรแทน · ลบ · CSV
- **สมัครแบบโรงเรียน** — ตรวจสลิปและอนุมัติ/ไม่อนุมัติ **ทั้งกลุ่มในคลิกเดียว**
- **จัดการผลสอบ** — พิมพ์คะแนน ระบบเลือก ผ่าน/ไม่ผ่านให้ตามเกณฑ์ · บันทึกทั้งหมดในครั้งเดียว · สวิตช์เปิด/ปิดประกาศผล
- **ข่าวสาร** — เพิ่ม/แก้ไข/ลบข่าว อัปโหลดรูปปก ปักหมุด
- **ตั้งค่าระบบ** — เปิด/ปิดรับสมัคร · ชื่อหน่วยงาน วันสอบ ค่าธรรมเนียม ข้อมูลติดต่อ บัญชีธนาคาร เกณฑ์ผ่าน บังคับ/ไม่บังคับรูปและสลิป
  ทั้งหมดแก้ในหน้าเว็บได้เลย **ไม่ต้องแก้โค้ด** · เปลี่ยนรหัสผ่าน

> **ลำดับสถานะ:** สมัคร → (แนบสลิป) → `รอตรวจสอบ` → เจ้าหน้าที่ `อนุมัติ` → พิมพ์บัตรได้
> ถ้า `ไม่อนุมัติ` ผู้สมัคร/ครูเห็นเหตุผล แก้ไขแล้วส่งสลิปใหม่ → กลับเป็น `รอตรวจสอบ` อัตโนมัติ

## ติดตั้งครั้งแรก (ใช้เวลาประมาณ 15 นาที)

### ขั้นที่ 1 — สร้างโปรเจกต์ Supabase
1. สมัครที่ [supabase.com](https://supabase.com) → **New project** (ตั้งชื่อ, ตั้งรหัสผ่านฐานข้อมูล, เลือก Region **Singapore** เพื่อให้เร็วที่สุดสำหรับไทย)
2. รอจนโปรเจกต์พร้อมใช้งาน (ประมาณ 2 นาที)

### ขั้นที่ 2 — สร้างตารางและระบบความปลอดภัย
1. เมนูซ้าย **SQL Editor** → **New query**
2. เปิดไฟล์ `supabase/schema.sql` คัดลอกทั้งไฟล์วาง → กด **Run**
3. ขึ้นว่า *Success* = เสร็จ (รันซ้ำกี่ครั้งก็ได้ ไม่ทำให้ข้อมูลหาย)

> **อัปเกรดจากเวอร์ชันเก่า (v1):** รันไฟล์ `schema.sql` ตัวใหม่ซ้ำใน SQL Editor ได้เลย ข้อมูลผู้สมัครเดิมไม่หาย
> ระบบจะเพิ่มตาราง/คอลัมน์ใหม่ให้ และ **ผู้ที่เคยมีสถานะ "ชำระแล้ว" จะถูกตั้งเป็น "อนุมัติแล้ว"** (ทำครั้งเดียว)
> จากนั้น push โค้ดหน้าเว็บตัวใหม่ขึ้น GitHub ด้วย (ควรรัน SQL ก่อน แล้วค่อย push)

### ขั้นที่ 3 — สร้างบัญชีเจ้าหน้าที่
1. เมนูซ้าย **Authentication → Users → Add user → Create new user**
   ใส่อีเมลและรหัสผ่าน (ติ๊ก *Auto Confirm User*)
2. กลับไป **SQL Editor** รันคำสั่งนี้ (แก้อีเมลให้ตรงกับที่สร้าง):
   ```sql
   insert into public.admins (user_id)
   select id from auth.users where email = 'admin@yourschool.ac.th';
   ```
3. จะเพิ่มเจ้าหน้าที่คนอื่นก็ทำซ้ำสองข้อนี้ — คนที่ไม่ได้อยู่ในตาราง `admins` ต่อให้ล็อกอินได้ก็ไม่เห็นข้อมูลผู้สมัคร

### ขั้นที่ 4 — ใส่คีย์เชื่อมต่อ
หาที่ **Project Settings → API**:

| ค่า | ใช้ทำอะไร |
|---|---|
| **Project URL** | ใส่ใน `SUPABASE_URL` |
| **anon public key** | ใส่ใน `SUPABASE_ANON_KEY` |

> ⚠️ ใช้ **anon** key เท่านั้น ห้ามใช้ `service_role` key ในหน้าเว็บ (ตัวตรวจใน workflow จะหยุดการ deploy ให้ถ้าพบ)

มี 2 วิธี เลือกอย่างใดอย่างหนึ่ง:
- **วิธี A (ง่ายสุด):** เปิด `assets/js/config.js` แล้วใส่ 2 ค่าตรง ๆ (anon key เป็นคีย์สาธารณะ ใส่ใน repo ได้)
- **วิธี B:** ใส่ใน GitHub (ขั้นที่ 6) แล้วไม่ต้องแตะไฟล์

### ขั้นที่ 5 — ส่งขึ้น GitHub
```bash
cd scimath-cloud
git init
git add .
git commit -m "ระบบรับสมัครสอบ SciMath Test"
git branch -M main
git remote add origin https://github.com/USERNAME/scimath-test.git
git push -u origin main
```

### ขั้นที่ 6 — เปิด GitHub Pages
1. repo → **Settings → Pages → Source: GitHub Actions**
2. (ถ้าเลือกวิธี B) **Settings → Secrets and variables → Actions**
   - แท็บ **Variables** → เพิ่ม `SUPABASE_URL`
   - แท็บ **Secrets** → เพิ่ม `SUPABASE_ANON_KEY`
3. แท็บ **Actions** → รอ workflow *Deploy to GitHub Pages* ขึ้นเครื่องหมายถูกสีเขียว
4. เว็บอยู่ที่ `https://USERNAME.github.io/scimath-test/`

### ขั้นที่ 7 — ตรวจสอบหลังขึ้นเว็บ
1. เปิดเว็บ → ต้องไม่มีแถบสีเหลือง/แดงด้านบน (ถ้ามีแปลว่าค่าใน config ยังไม่ถูกต้อง)
2. ลองสมัครสอบ 1 รายการพร้อมรูป
3. **สำหรับเจ้าหน้าที่** → ล็อกอิน → ต้องเห็นรายการที่เพิ่งสมัคร
4. กด "ยืนยันชำระ" → กด "บัตรสอบ" → ตรวจว่าบัตรแสดงรูปและข้อมูลครบ
5. ทดสอบ **ล็อกอินผู้สมัคร** ด้วยเลขบัตร+วันเกิดที่ใช้สมัคร → ต้องพิมพ์บัตรได้
6. ที่ **ตั้งค่าระบบ** แก้ชื่อหน่วยงาน วันสอบ ข้อมูลติดต่อ บัญชีธนาคาร ให้เป็นของจริง แล้วกดบันทึก

## การใช้งานประจำ

| งาน | ทำที่ไหน |
|---|---|
| ปิด/เปิดรับสมัคร | สำหรับเจ้าหน้าที่ → ตั้งค่าระบบ → สวิตช์ |
| ตรวจสลิปและอนุมัติ | ผู้สมัครสอบ → ปุ่ม "ตรวจสอบ" → อนุมัติ / ไม่อนุมัติ (ใส่เหตุผล) |
| อนุมัติหลายคนพร้อมกัน | ผู้สมัครสอบ → ติ๊กหน้าแถว → "อนุมัติที่เลือก" |
| อนุมัติกลุ่มโรงเรียน | สมัครแบบโรงเรียน → "ตรวจสอบ" → อนุมัติทั้งกลุ่ม |
| ลงข่าว / ปักหมุด | ข่าวสาร → กรอกหัวข้อ เนื้อหา รูปปก → เพิ่มข่าว |
| กำหนดห้องสอบ/เลขที่นั่ง | ผู้สมัครสอบ → "แก้ไข" |
| ลงคะแนน | จัดการผลสอบ → พิมพ์คะแนน → "บันทึกทั้งหมด" |
| ประกาศผลให้ผู้สมัครเห็น | จัดการผลสอบ → สวิตช์ "ประกาศผลสอบ" (ผู้สมัครจะเห็นคะแนนเฉพาะหลังเปิดสวิตช์นี้) |
| ส่งรายชื่อให้ฝ่ายอื่น | ผู้สมัครสอบ → "ดาวน์โหลด CSV" (เปิดใน Excel ภาษาไทยได้ปกติ) |
| แก้ไขเว็บ (โค้ด/ข้อความ) | แก้ไฟล์แล้ว `git push` เว็บอัปเดตเอง |
| ดูข้อมูลดิบ/สำรองข้อมูล | Supabase → **Table Editor** (Export เป็น CSV ได้) |

**ควรสำรองข้อมูล** ก่อนปิดรับสมัคร และก่อนประกาศผล: Supabase → Table Editor → ตาราง `applicants` → Export CSV
(แพ็กเกจฟรีของ Supabase ไม่มีการสำรองอัตโนมัติ ถ้าต้องการให้ระบบสำรองรายวัน ต้องใช้แพ็กเกจ Pro)

## แก้ปัญหา: GitHub Actions ขึ้นกากบาทแดง

เข้าแท็บ **Actions** → คลิกรายการที่ล้มเหลว → คลิกชื่อ job ทางซ้าย → ดูว่า **ขั้นตอนไหนมีกากบาทแดง** แล้วดูตารางนี้

| ขั้นตอนที่ล้ม | สาเหตุที่พบบ่อย | วิธีแก้ |
|---|---|---|
| `Guard - refuse to publish a secret key` | ใส่ `service_role` / `sb_secret_` key ลงไป (ถูกบล็อกถูกต้องแล้ว) | ใช้ **anon / publishable** key แทน และไปสร้างคีย์ใหม่ที่ Supabase เพราะคีย์ที่หลุดไปแล้วถือว่าไม่ปลอดภัย |
| `Check JavaScript syntax` | แก้ไฟล์ใน `assets/js/` แล้วมี error | เปิด log ดูบรรทัดที่ error แล้วแก้ |
| `configure-pages` ขึ้น *Get Pages site failed / Not Found* | ยังไม่ได้เปิด Pages | **Settings → Pages → Source = GitHub Actions** แล้วกด *Re-run all jobs* |
| `configure-pages` / `deploy` ขึ้นว่า Pages ไม่รองรับ | repo เป็น **Private** บนแพ็กเกจ GitHub Free (Pages ใช้กับ repo Private ไม่ได้) | ตั้ง repo เป็น **Public** (ในโค้ดไม่มีข้อมูลลับ anon key เป็นคีย์สาธารณะ ข้อมูลผู้สมัครอยู่ใน Supabase ไม่ได้อยู่ใน repo) หรืออัปเกรดแพ็กเกจ |
| `deploy` ค้างนาน / *waiting for approval* | Environment `github-pages` ตั้งให้ต้องอนุมัติ | **Settings → Environments → github-pages** ปิด *Required reviewers* หรือกด Approve |

หลังแก้แล้ว กด **Re-run all jobs** ที่หน้ารายการนั้น ไม่ต้อง push ใหม่ (ยกเว้นแก้ไฟล์)

## HTTPS (เว็บแบบ https://)

**ถ้า deploy ด้วย GitHub Pages (วิธีที่แนะนำ) — ได้ HTTPS ฟรีอัตโนมัติ**
- ที่อยู่ `https://USERNAME.github.io/...` เป็น HTTPS อยู่แล้ว ไม่ต้องตั้งค่าอะไร
- ถ้าใช้โดเมนของตัวเอง (เช่น `test.yourschool.ac.th`):
  1. repo → **Settings → Pages → Custom domain** ใส่โดเมน แล้ว Save
  2. ที่ผู้ให้บริการโดเมน เพิ่ม DNS
     - โดเมนย่อย (`test.yourschool.ac.th`): ระเบียน **CNAME** ชี้ไป `USERNAME.github.io`
     - โดเมนหลัก (`yourschool.ac.th`): ระเบียน **A** 4 ตัว ชี้ไป `185.199.108.153`, `185.199.109.153`, `185.199.110.153`, `185.199.111.153`
  3. รอ DNS อัปเดต (นาที–ชั่วโมง) แล้วกลับมาติ๊ก **Enforce HTTPS** (ใบรับรอง Let's Encrypt ออกให้อัตโนมัติ)

**ถ้าใช้ hosting / VPS ของตัวเอง** — โฟลเดอร์ `https/` มีไฟล์ตั้งค่าพร้อมใช้:

| ไฟล์ | ใช้กับ | วิธีใช้ |
|---|---|---|
| `https/apache.htaccess` | Apache / cPanel | คัดลอกไปไว้ที่โฟลเดอร์รากเว็บ ตั้งชื่อ `.htaccess` (เปิด SSL ใน cPanel ได้ที่ *SSL/TLS Status → Run AutoSSL*) |
| `https/nginx.conf` | VPS (Nginx) | แก้โดเมน/พาธ แล้วรัน `certbot --nginx` เพื่อออกใบรับรองฟรี |
| `https/_headers` | Netlify / Cloudflare Pages | วางไว้ที่รากเว็บ (HTTPS อัตโนมัติอยู่แล้ว ไฟล์นี้เพิ่มหัวความปลอดภัย) |

**ที่ฝังไว้ใน `index.html` แล้ว** (ทำงานได้แม้ host ไม่มีสิทธิ์ตั้งค่า server เช่น GitHub Pages):
- สคริปต์เด้งจาก `http://` ไป `https://` อัตโนมัติ (ไม่ทำงานบน localhost)
- Content-Security-Policy จำกัดให้โหลดสคริปต์/ข้อมูลเฉพาะจาก jsDelivr, Google Fonts และ `*.supabase.co`
  พร้อม `upgrade-insecure-requests` (ถ้าบังเอิญมีลิงก์ http จะถูกยกระดับเป็น https)
- หมายเหตุ: ถ้าใช้ **โดเมน Supabase ของตัวเอง** (Custom domain) ต้องเพิ่มโดเมนนั้นใน `connect-src` ทั้งใน `index.html` และไฟล์ใน `https/`
  และ GitHub Pages ตั้ง HTTP header เองไม่ได้ จึงได้เฉพาะ CSP แบบ meta (ไม่มี HSTS / `frame-ancestors`)

**เวอร์ชัน PHP+MySQL:** ใช้ไฟล์ `apache.htaccess` / `nginx.conf` ด้านบนได้เช่นกัน และควรเพิ่ม 4 บรรทัดนี้ใน `config.php`
**ก่อน** `session_start()` เพื่อให้คุกกี้ล็อกอินส่งผ่าน HTTPS เท่านั้น:
```php
session_set_cookie_params([
    'secure'   => true,      // ส่งคุกกี้เฉพาะผ่าน https
    'httponly' => true,      // JavaScript อ่านคุกกี้ไม่ได้
    'samesite' => 'Lax',
]);
```

## ความปลอดภัย — ออกแบบอย่างไร

- **ผู้ใช้ทั่วไปอ่านตารางผู้สมัครตรง ๆ ไม่ได้เลย** ทุกอย่างผ่านฟังก์ชันฝั่งฐานข้อมูลที่ต้องกรอกเลขบัตรและวันเกิดให้ตรงก่อน
  จึงได้เฉพาะข้อมูลของตัวเอง (ทดสอบด้วย PostgreSQL จริงแล้ว: anon อ่านตาราง = ถูกปฏิเสธ)
- **คะแนนไม่หลุดก่อนประกาศผล** — ฟังก์ชันจะตัดคะแนนออกจนกว่าเจ้าหน้าที่เปิดสวิตช์ประกาศผล
- **เจ้าหน้าที่ต้องล็อกอิน Supabase Auth และอยู่ในตาราง `admins`** จึงจะอ่าน/แก้ข้อมูลได้
- การสมัครตรวจซ้ำที่ฝั่งฐานข้อมูล (ไม่เชื่อหน้าเว็บ): ปิดรับสมัคร, เลขบัตรซ้ำ, วิชาปลอม, ค่าธรรมเนียม (คำนวณเอง), ชนิดรูป
- ข้อมูลที่ผู้สมัครกรอกถูก escape ก่อนแสดงทุกจุด (กัน stored XSS ที่จะไปโจมตีเจ้าหน้าที่) และ CSV กัน formula injection

**สิ่งที่เพิ่มใน v2**
- สลิปและรูปถ่ายอ่านได้เฉพาะเจ้าหน้าที่ และเจ้าของข้อมูล (ผ่านฟังก์ชันที่ตรวจตัวตน) — ครูเห็นเฉพาะนักเรียนในกลุ่มของตนเท่านั้น
- ครูอัปโหลดรูป/สลิปได้เฉพาะกลุ่มของตน และ **แก้สลิปไม่ได้หลังอนุมัติแล้ว**
- สถิติหน้าแรกเป็นตัวเลขรวมเท่านั้น ไม่เปิดเผยข้อมูลรายบุคคล

**ข้อจำกัดที่ควรรู้**
- ครูที่ปรึกษาเข้าสู่ระบบด้วย "เลขบัตรครู + เบอร์โทรที่กรอกไว้" ซึ่งไม่ใช่รหัสผ่านที่เดาไม่ได้ ผู้ที่รู้ทั้งสองอย่างจะเห็นรายชื่อและอัปโหลดรูปให้กลุ่มนั้นได้ (ดูบัตรที่พิมพ์ได้เฉพาะเมื่ออนุมัติแล้ว) ควรเปิด Rate Limits ตามด้านล่าง
- สลิป ~100–300 KB ต่อใบ + รูปถ่าย ~30–50 KB ต่อคน เก็บในฐานข้อมูล: โควตา 500 MB ของแพ็กเกจฟรีรองรับได้ราว 1,500–3,000 ใบสมัครที่มีสลิปแยกรายบุคคล (กลุ่มโรงเรียนใช้สลิปเดียวต่อกลุ่ม จึงประหยัดกว่า) ถ้าจะรับมากกว่านี้ ให้ย้ายไป Supabase Storage
- การเข้าสู่ระบบผู้สมัครใช้ "เลขบัตร + วันเกิด" (ไม่มีรหัสผ่านแยก) ตามรูปแบบเว็บต้นแบบ ผู้ไม่หวังดีที่รู้ข้อมูลสองอย่างนี้ของเด็กจะเห็นข้อมูลเด็กคนนั้นได้
  และ Supabase ฟรียังไม่ได้กันการลองสุ่มเลขจำนวนมาก ถ้ากังวล ให้เปิด **Authentication → Rate Limits** และพิจารณาเพิ่ม CAPTCHA (Cloudflare Turnstile) ตอนสมัคร
- รูปถ่ายเก็บเป็นข้อมูลในฐานข้อมูล (ย่อให้ ~30–50 KB/คน) เหมาะกับหลักพันคน ถ้าเกินหลายพันคนควรย้ายไป Supabase Storage
- รูปถ่ายและเลขบัตรเป็นข้อมูลส่วนบุคคลตาม PDPA — ควรมีข้อความแจ้งวัตถุประสงค์ และลบข้อมูลเมื่อสิ้นสุดโครงการ
- แพ็กเกจฟรีของ Supabase จะ **พักโปรเจกต์ที่ไม่มีการใช้งานนาน 7 วัน** (กดเปิดกลับได้ใน Dashboard) ช่วงรับสมัครจริงมีคนใช้งานตลอดจึงไม่ใช่ปัญหา แต่ควรเช็กก่อนวันเปิดรับสมัคร

## ใช้ host อื่นแทน GitHub Pages ได้ไหม
ได้ — ทั้งโฟลเดอร์ที่ต้องใช้มีแค่ `index.html` กับ `assets/` เป็นไฟล์ static ล้วน
อัปโหลดไป Netlify, Cloudflare Pages, Firebase Hosting หรือ hosting ปกติ (แค่โยนไฟล์ขึ้น) ได้เลย
